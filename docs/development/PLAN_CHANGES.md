# 개발기획서 대비 현재 구현과 변경 이유

기준일: 2026-10-20. 이 문서는 구현 현황 설명이며 원 개발기획서의 수정 제출본을 대신하지 않는다.
원문은 사용자 제공 `[소개딩] 개발기획서_팀 인과함께_최종.pdf`다. PDF 4쪽의 F1~F5·3단계 판정,
5쪽 기술 구성, 8쪽 목표를 로컬 페이지별 추출문 `references/extracted/P1.txt`와 대조했다.
원 PDF·추출문은 이 게시 묶음에 재배포하지 않는다. 과거 설계/인계 문서의 상태는 작성 당시의 기록이다.

## 그대로 유지한 핵심

- F1/F2: 신뢰된 adapter가 사용자 입력과 실제 읽기 결과의 출처를 구분하고, 요청·자료·호출·판정·실행을 연결한다.
- F3: 서버 코드 정책을 먼저 적용하고 필요한 후보에서만 출처·의미를 분석한다. 모델이 실행 권한을 새로 발급하지 않는다.
- F4: 위험 후보는 실행 전에 거절한다. 판정과 실제 효과를 따로 기록한다.
- F5: 사용자는 이력과 예외 확인을 화면에서 확인한다. 화면은 권한·판정을 임의로 바꾸지 않는다.

등록 MCP의 제한된 실제 실행 증거와 합성 응답 기반 제어 흐름 시험은 구분한다.
정상 업무가 계속 완료되는 목표는 일부 확인했지만 일반화가 완료된 것은 아니다.

## 판정 방식에서 실제로 바뀐 부분

| 원 기획의 내용 | 현재 방식 | 이유와 의미 |
|---|---|---|
| 읽기 전용은 1단계에서 통과(PDF4) | 등록 schema·사용자 권한·민감성·탐색 범위가 확인된 조회만 코드 ALLOW | 비밀 읽기나 비공개 재귀 검색도 위험 효과를 만들 수 있어 도구 이름만으로 허용하지 않음. 정상 범위 내의 읽기 지원 확대는 계속 필요 |
| 외부에만 있는 값을 그대로 쓰면 공격 탐지(PDF4) | 외부 값은 정상 데이터로도 쓸 수 있음. 실제 후보의 목적·내용과 사용자 금지/권한을 함께 판단 | 정상 제목·경로·인용·요약도 외부 값을 사용하므로 단순 출처 일치만으로 DENY하면 과차단. 출처 일치는 관측 근거이며 인과/권한 증명 아님 |
| 같은 질문을 외부 자료 전후에 두 번 비교(PDF4) | A는 사용자 요청과 후보의 업무 범위, B는 자료까지 포함한 현재 행동의 적합성 | 현재 구현은 서로 다른 질문이다. 차이를 인과 효과로 계산하지 않고 행동 판정을 합성한다. 원 기획과 동일 방식이라고 설명하지 않음 |
| 원인 역추적·정밀 출처 연결을 판정에 활용(PDF2~4) | 원문/hash/span 연결 무결성은 유지하되 행동 적합성과 정확한 span 귀속은 분리 | 실제 V4에서 외부 지시 채택은 높은 확신이어도 정확한 span 지지가 낮아 CONFIRM으로 약화됐음. 위험 관측을 정밀 귀속의 불확실성 때문에 해제 가능한 상태로 낮추지 않기 위한 변경 |
| 사용자 확인을 포함한 반복 위험 대응(PDF4) | 확정 DENY는 승인 불가. 사용자 범위 안의 모호한 CONFIRM만 정확한 단회 승인 | 반복 요청·사람 확인이 금지 정책을 우회하는 경로가 되지 않게 함. UNKNOWN의 위험 쓰기는 자동 재시도하지 않음 |

후속 정책 결정도 버전별로 구분한다.

- [ADR-P02](../plans/decisions/ADR-P02_selective_provenance_adoption.md): 실제 schema의 action/target/options/payload,
  복수 출처·문맥 관측을 선택적으로 채택. inline 마커 삽입/제거는 MVP에서 제외.
- [ADR-P03](../plans/decisions/ADR-P03_decision_attribution_separation.md): 행동 판정과 정밀 귀속 분리.
- [ADR-P04](../plans/decisions/ADR-P04_b_owned_positive_authorization.md): 등록 파일 MCP에서 B의 정상 허용 책임 조정.
  A의 낮은 confidence를 올린 수치 수리가 아니라 실제 정책 변경이며 고확신 오판 위험은 남는다.
- [시연 개선 계획](../plans/18_practical_demo_improvement.md): 별도 DTAP/시연 프로필에 한해 정상 허용 기준 `.50` 실험.
  기존 전역 기준·과거 결과를 바꾸지 않으며 모델 정확도 개선 완료로 해석하지 않는다.

주요 코드: `src/app/transparent/jev.py`, `jev_decision_v5.py`, `jev_core_v5p1.py`,
`src/app/benchmark/runtime_policy.py`, `demo_policy.py`, `task_scope.py`, `query_capability.py`.
프로필마다 질문·조건·임계치가 다를 수 있어 비교 시 health/정책 ID·원 응답을 기록한다.

## 기술 구성과 사용 범위의 변경

| 원 기획(PDF3~5) | 현재 구현 | 선택 이유·미완료 |
|---|---|---|
| PostgreSQL·Redis·OpenTelemetry | SQLite·세션/turn/call/source ID·hash | 단일 호스트 구현·재현을 줄이기 위한 선택. 분산 저장·관측이나 해시체인 완성은 아님 |
| agentgateway + gRPC ext_authz, LiteLLM | 실제 agentgateway + HTTP extAuthz + HTTPS/mTLS, Python Control | JSON-RPC 도구 인자와 출처·판정·서명을 결합한 실행 전 통제를 실제 검증. gRPC·LiteLLM·A2A/전체 LLM 트래픽 보호는 미구현 |
| Claude Code·Codex·GitHub MCP 등 | Codex hooks와 등록 합성 파일 MCP 우선, 별도 DTAP OS 어댑터 | 실제 효과를 통제·검증하는 좁은 경로부터 구현. OS 전체·임의 도구 호환성은 미완료 |
| Streamlit 그래프·차단 사유·오탐 표시 | 최소 HTML/터미널 이력과 조회·승인 API. 팀원이 별도 대시보드 개발 | 엔진 집행·승인 상태를 먼저 확인. 프론트와 인증/API를 맞추는 작업은 남음. Streamlit 채택 완료 아님 |
| Docker·GitHub Actions·AWS EC2 | 로컬 Docker Compose·잠금 의존성·대표 시험·공유 개발 초기화 | 클론 기반 공동 개발 준비. 운영 배포·자동 CI/CD·전수 보안 진단 완료는 아님 |

F1~F5를 포기한 변경과 완료 범위를 혼동하지 않는다. 출처·집행의 핵심은 유지하지만
보호 대상·성능·정상 업무 지속성·UI의 원 기획 전체 요구가 충족된 상태는 아니다.
현재 [README](../../README.md)의 미완료 항목과 [팀원 인계](TEAM_HANDOFF.md)를 함께 본다.

## 남은 네 작업의 성격

1. **DTAP:** 평가 실행·연결 안정화·유효한 off/on 비교. 발견한 문제에 따라 엔진이나 어댑터를 수정한다.
   미완료/UNKNOWN/CONFIRM을 공격 차단 성공으로 합산하지 않는다. 코드 DENY와 Jev 의미 DENY도 분리한다.
2. **정상 업무 호환성:** 사용자가 허용한 정상 일을 불필요하게 멈추지 않도록 도구·범위·후속 진행을 보완한다.
   실제 권한·동의가 필요한 CONFIRM은 유지한다. DTAP 전용 도구의 결함을 공통 제품 전체의 결함으로 확대하지 않는다.
3. **Jev 조정:** 현재 요청/후보/출처를 구분하는 질문·입력, 호출 여부, 응답 검증, 최종 정책을 개선한다.
   Jev 가중치를 재학습하거나 낮은 confidence를 높은 값으로 바꾼 작업이 아니다.
4. **대시보드 연동:** 이미 있는 이력/승인과 팀원 화면의 API·인증·상태를 맞춘다. DTAP 화면은 포함하지 않는다.

2·3이 직접적인 엔진 개선이고 1은 검증/통합, 4는 제품 연동이다.
원 기획 PDF8의 공격 차단률 90% 이상·정상 과차단률 10% 이하·저비용 단계 50ms 이하와
사용자 확인 최소화는 아직 달성 근거가 없는 목표다. 시험 통과 수나 일부 사례를 해당 수치로 환산하지 않는다.
