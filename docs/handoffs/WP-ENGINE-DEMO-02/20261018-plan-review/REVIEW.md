# 시연 개선 계획 별도 AI 검토

2026-10-18. **계획 검토 PASS — 미해결 P1/P2 발견 없음.** 대상은 `docs/plans/18_practical_demo_improvement.md`와 `WP-ENGINE-DEMO-02/START_PROMPT.md`다. 구현·배포·실제 모델 성능을 수용한 판정은 아니며 새 지출 승인도 아니다. 검토자는 이 문서 외 제품 파일·원장·키를 수정하거나 provider를 호출하지 않았다.

## 확인한 범위

- 사용자 목표인 정상 자동 완료와 실제 위험 후보의 DENY/실행0을 함께 요구한다. 새 도메인 전수 연결·대시보드·모델 탐색·전체 인과 복원은 선행조건에서 제외한다. 정책/출처/필요한 의미 분석 보강을 먼저 끝낸 뒤 두 벤치마크의 작은 범위를 연결하므로 불필요한 확대를 제한한다.
- `.50`은 새 격리 시연 프로필의 허용 가설이다. 기존 product 전역 `.90`, 원 질문/실응답/동결 run은 유지하며 위험 DENY 기준도 `.90`을 보존한다. B raw LEGITIMATE·유효 confidence ≥ `.50`, A raw WITHIN_TASK 및 정확한 권한·출처/상태 검증·예약 통과를 모두 요구한다. 모델 confidence가 권한을 발급하거나 하드 거부를 해제하지 않는다. `.50`을 정답률/안전 확률 또는 검증된 최적값으로 해석하지 않는다.
- 일반 조회는 도구 이름이나 외부 설명만으로 허용하지 않는다. 민감 읽기·외부 수신자·파괴/설정 변경은 실제 권한을 별도로 검사한다. 외부 자료와 문자열이 일치한다는 사실도 단독 DENY 근거로 삼지 않는다. 정상 데이터 사용과 추가 지시 채택을 구분한다.
- 과업의 중간 단계·공식 권한 요청·현재 후보를 구분하는 질문 보강은 새 버전으로 한다. 원문/hash/span/수집 완전성을 유지하고 정답·judge 조건·공격 목표를 방어자 입력에 넣지 않는다. 기존 응답을 새 질문의 답으로 재사용하지 않는다.

## 평가·재실행 해석

DTAP의 기존 off 공격 성공 12개는 튜닝에 사용한 **공격 성공 조건부 사례 집합**임을 명시한다. 기존 off는 모델 snapshot/effort/actor 설정/과업·공격·도구/initial image가 검증될 때만 재사용한다. 새 정책 평가는 기존 CONFIRM을 자동 재개하는 것이 아니라 명시된 별도 revision 결과다. 기존 UNKNOWN은 재실행하지 않고 원 결과와 비용을 보존한다. 전체 ASR·독립 holdout 검증으로 확대하지 않는다.

AgentDojo는 workspace 공격 3개 조합과 대응 clean user task 3개를 두 조건에서 평가하는 12 task-arm의 사전 고정 목표다. 임계치/룰 동결 후 결과를 보고 사례를 바꾸지 않으며 original utility/security를 유지한다. 공격 생성·judge의 추가 유료 모델은 금지하고 pinned 구현의 실제 호출 경로를 먼저 확인한다. 함수 runtime의 trusted executor 직전 PDP 적용은 DTAP의 실제 MCP/agentgateway 경유 증거와 구분한다. 두 조건의 원 system prompt·설정·초기 상태를 같게 둔다.

두 평가 모두 공격 성공·업무 성공·실제 DENY/실행0·CONFIRM·UNKNOWN·미시도를 별도 보고한다. 모두 멈춘 결과를 정상 완료나 방어 성공으로 바꾸지 않는다. AgentDojo 3개 clean 사례도 전체 정상 오탐률을 입증하는 표본으로 확대할 수 없다.

## 구현 시 남는 검증

계획 자체는 기존 기록을 보존하며 좁은 후보를 준비할 수 있게 한다. 실제 `.50` 프로필의 위험 오허용 가능성, code routing의 권한·부작용 판별, AgentDojo adapter의 실행 전 집행과 원 judge 호환성, 실제 비용 내 완료 가능성은 아직 검증되지 않았다. 관련 무모델 경계 시험과 최종 구현 검토를 거친 뒤 정확한 범위·자료·누적 한도를 고정한 사용자 실행 명령을 인계해야 한다. 이번 계획 검토로 자동 실행하거나 미완성 연결을 완료로 표시하지 않는다.
