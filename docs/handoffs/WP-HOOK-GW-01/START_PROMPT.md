# WP-HOOK-GW-01 개발 세션 시작 지시

with-human-dev 스킬을 사용하되, 아래 사용자 명시 변경과 관리 작업팩13이 기존 고정3도구·단일과업 실험 범위보다 우선한다.

사용자가 원하는 MVP는 개발자가 자신의 단말에서 평소처럼 `codex`를 켜고 자유롭게 개발할 때, hooks와 실제 agentgateway가 사용자 입력/출처/도구 호출을 자동으로 PDP에 연결해 실행 전에 판정하고 차단하는 제품이다. 사전 대시보드 작업 생성·수동 agent token 복사·이슈42/댓글1회 제한을 제품의 기본 흐름으로 다시 만들지 말라. 세션/머신 인증과 출처 결합은 신뢰된 연결 모듈이 자동 처리한다.

먼저 `docs/plans/13_transparent_codex_gateway_mvp.md`, AGENTS.md, docs/plans/03_guide_compliance.md, 현재 docs/mvp와 기존 WP-F3-01 manual 인계/최초 실제 실패를 읽고 실제 변경 상태를 확인하라. 관련 필수 가이드의 원문 페이지를 코드·위협·시험에 연결하라. 관리 문서/장부는 읽기 전용이다.

개발은 작업팩13의 순서대로 단일 세션에서 통합하라. 실제 Windows CLI hook의 사용자 입력·실행 전 deny·도구 결과 수집과 agentgateway의 tool 인자/본문·extAuthz·upstream 효과0을 먼저 검증하고, 자동 turn/출처/call 계약과 기존 PDP를 연결하라. SPEC4 모의 실험은 보존하며 SPEC5 개정은13번 범위에서 위임됐다. native hook와 MCP/gateway 경로를 혼동하지 말고 실제 지원 매트릭스를 남겨라.

기존 출처·정책·의미 판정/진단·암호화·TLS·원자 예약·예외 승인/UNKNOWN 통제는 재사용하라. 원문/ref 검증이나 보안 실패 차단을 끄지 말라. 호출 관측만으로 실행 전 집행을 주장하지 말고, upstream에 모의 실행기의 receipt/멱등성을 그대로 가정하지 말라. 정상 파일 편집/지원 tool 작업까지 항상 차단하거나 개발 도구를 모두 끄는 것으로 기능을 대체하지 말라.

지원/쓰기 범위, 금지 범위와 완료 기준은13번을 따른다. 개인 Codex 전역 설정·인증·전역 CA·기존키/DB/예산/원증거를 변경·초기화하지 말라. 모델 없는 검증을 우선하고 개발 AI의 유료 호출/예산 증액은 하지 말라. 실제 모델은 사용자가 직접 실행하도록 남겨라. 새로운 도구/이미지는 공식 출처·고정 버전·무결성·라이선스/공급망 증거를 남겨라.

정상 자유 입력과 후속 사용자 turn, 정상 외부자료 활용, 외부 지시에 따른 위험 후보의 실행 전 차단/효과0, 위조·장애·인자변조·재전송/UNKNOWN을 검증하고 별도 AI 검토를 받아라. 공격 미시도/분석 오류는 공격 식별 PASS가 아니다. 기존3도구 시험 PASS로 새 제품 완료를 대신하지 말라.

`docs/handoffs/WP-HOOK-GW-01/<run_id>/RESULT.md`와 별도 REVIEW로 실제 변경·명령/소스·정상/금지 효과·실패/미실행/미지원·사용자 최소 설치 및 직접 CLI 절차를 인계하라. 전역 DONE/MVP 완료는 관리 세션이 판단한다.
