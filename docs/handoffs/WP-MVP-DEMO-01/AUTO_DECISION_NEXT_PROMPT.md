## 이번 좁은 작업

1. **기계 정밀도 경계 수리.** 실제 basis_target은 USER .92/5choices에서 계산상 .90, provider .90인데 float .8999999999999999 때문에 .90 검사를 실패했다. 이 산술 재현과 경계 바로 아래/위 반례를 먼저 만든다. 입력의 실제 낮은 confidence나 확률을 승격하지 않고 수학적으로 동등한 기계 정밀도만 다룬다. 임계치 .90 자체나 기존 응답 계약의 유효성/usage/ref 검증을 바꾸지 않는다. 다른 .83/.5375/.38 미달은 이 문제와 구별한다.
2. **출처/slot 질문의 실제 입력 확인.** USER action, TASK_DATA payload는 선택됐지만 낮은 confidence/link 때문에 막혔다. A/B wire state·criteria·evidence key가 정확히 대응하는지, 도구 결과가 MCP JSON envelope/escaped 문자열로만 전달돼 본문과 span 연결을 어렵게 하는지 기존 공개 자료/실응답으로 모델0 확인한다. 전체 원 암호화 snapshot을 복원했다고 하지 않는다. 표현 문제가 확인되면 원문/hash/정확 catalog/ref 연결을 보존한 최소 의미 입력 정리만 한다. 확인되지 않은 원인을 사실로 단정하거나 질문을 반복해서 바꾸지 않는다.
3. **필요한 판정만 요구.** 신뢰된 사용자 요청의 권한/행동, 사용자 지정 대상, 외부 payload/옵션/추가 행동을 구별한다. 서버가 검증하는 catalog membership과 모델의 의미 판단을 혼동하지 않는다. 같은 허용 의미 사이의 분산·무관 링크를 위험 불확실성과 섞지 않는다. 확실한 외부 추가 행동은 DENY 우선이고, 실제 모호함은 CONFIRM이다. 새로운 질문/내부 정책 계약 변경은 이 범위로 위임하되 새 버전과 이전 응답 재현을 분리한다. raw 일치만으로 권한 부여/위험판정 생략/정상 전부 사람 승인/기준 임의 하향/경로·case 정답 하드코딩은 금지한다.

- 기존 실제 선택/확률을 그대로 넣어 현재 CONFIRM을 재현한다. 새 질문의 fake 응답을 실제 Jev 결과로 가장하지 않는다. 정상 한국어 사실 요약·합법적 지침·인용/금지·다중 출처와 외부 target/options/거짓보고 추가 행동의 반례를 관련 시험으로 확인한다.
