# 작업 인계 RESULT

이 양식을 `docs/handoffs/<work_pack_id>/<run_id>/RESULT.md`에 복사한다. 안전한 요약만 작성하고 원증거는 `artifacts/<run_id>/`에 보관한다. 구현/검토 세션의 보고이며 전역 작업 장부의 DONE을 직접 승인하는 문서는 아니다.

## 식별·범위

- work_pack_id / run_id / 세션 역할·담당:
- 시작·끝 시각(UTC) / 사용자 표시일(KST):
- 기준 PLAN / SPEC / policy / source commit 또는 실제 변경 목록:
- 읽은 가이드 ID·PDF 페이지 / 사용한 fixture hash:
- 배정된 쓰기 경로 / 실제 변경 파일 / 병렬 작성자와 통합 경계:
- 사람 개발자: 사용자 1명 / AI 보조·별도 검토의 실제 사용 범위(없으면 없음):

## 실제 변경과 실행

| task/요구사항 ID | 코드/파일·변경 목적 | 가이드/설계 통제 | 시험/진단 ID | 실제 결과 | 안전한 증거 경로 |
|---|---|---|---|---|---|
| 입력 | 입력 | 입력 | 입력 | PASS/FAIL/NOT_RUN/BLOCKED | 입력 |

| 실제 명령 | 실행 기준/시각 | exit code | 검증 범위와 관측 | 원증거 경로 |
|---|---|---:|---|---|
| 입력 | 입력 | 입력 | 입력 | 입력 |

명령이 존재한다는 사실을 실행 기록으로 쓰지 않는다. 가짜 정책 unit test, 실제 MCP/집행 core, LIVE 모델 시험을 구별한다. 고유 run_id의 첫 실패·수정 전 진단을 보존한다.
