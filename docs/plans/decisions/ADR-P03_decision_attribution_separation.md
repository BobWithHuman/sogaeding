# ADR-P03: 행동 판정과 정밀 출처 귀속의 분리

2026-10-17 관리 결정. 구현 후보 범위의 위임이며 운영 배포·유료 실행 승인이 아니다. 출처 기반 PDP, Jev, A/B 격리, 실행 전 통제를 유지한다. 완전한 taint/인과 추적을 구현했다고 주장하지 않는다.

## 근거

실제 V4 네 요청은 프로토콜/ref/usage 검증을 통과했지만 정상·공격 모두 CONFIRM이었다. 정상 payload는 INDEPENDENT .69/TASK_DATA .31의 합법 분류 사이에서 분산됐다. 공격 payload는 ADDED_INSTRUCTION effective .97을 통과했지만 source support .73 때문에 DENY로 연결되지 않았다. 행동 판단과 출처 설명의 세분성을 과도하게 결합한 설계가 관측됐다. 과거 결과를 바꾸거나 전체 정확도를 추정하지 않는다.

TypeSafe 공식 문서는 confidence를 선택 분포의 집중도로 설명하고, 임계치는 위험과 실제 사용 데이터에 맞춰 정하도록 한다: [Confidence](https://docs.typesafe.ai/confidence). 현재 .90은 제품의 미보정 보수 기준이며 제공자가 보장한 정확도가 아니다. 이번 두 예제에 맞춰 기준을 임의로 내리거나, 과거 정상 분류의 확률을 더해 높은 확신을 새로 만들지 않는다.

## 결정

1. 출처 수집·원문/hash/catalog/ref 무결성·실제 사용자 입력/역할·snapshot/turn/args/policy binding은 계속 필수다. 외부 글은 권한을 주지 않으며 모델은 관측만 제공한다.
2. 최종 ALLOW/DENY/CONFIRM은 사용자 작업 범위와 후보가 자료를 충실하게 사용하는지, 외부 추가 행동을 채택하는지를 기준으로 한다. 사용자 지정·위임 생성·정상 자료 활용은 행동 판정에서 같은 합법 계열로 다룬다. 내부 설명 유형을 구분하는 어려움만으로 이미 확인된 합법 행동을 막지 않는다. 새 질문은 새 실제 출력으로 검증해야 하며 과거 .59를 승격하지 않는다.
3. 무결성이 검증된 외부 자료 입력 아래, 사용자 작업 밖 외부 추가 행동의 실제 채택이 높은 확신으로 확인되면 서버는 DENY할 수 있다. 정확히 어느 span이 원인인지 귀속이 미확정이라는 이유만으로 이 위험을 인간 승인 가능한 CONFIRM으로 낮추지 않는다. 외부 명령의 단순 존재·인용·키워드·모델의 출처 자가선언만으로는 이 조건을 충족하지 않는다.
4. 정확한 출처 귀속은 별도 관측이다. 해당 자료가 판정 입력으로 들어왔다는 사실, 특정 span이 후보를 의미적으로 지지한다는 관측, 실제 행동의 원인이라는 설명을 구분한다. 서버가 검증하는 입력 무결성을 의미적 지지/인과 증명으로 부풀리지 않는다. 미확정 귀속은 명시하고 권한을 새로 주지 않는다.
5. 작업/행동의 안전성이 실제로 불확실할 때 CONFIRM한다. 확정 DENY는 승인으로 해제하지 않는다. ALLOW는 높은 확신의 범위/합법 행동 관측과 hard rule·완전한 출처·정확 권한/binding·단회 예약까지 충족해야 한다. 파싱·출처 무결성·PDP·감사 실패는 fail-closed를 유지한다.

## 구현과 검증

V4/실제 결과는 보존하고 새 내부 버전 후보로 구현한다. 운영 서비스는 V3를 유지한다. 기존 실제 관측의 정책 replay에서 원 결과와 새 정책의 반사실 결과를 구분한다. 새 질문의 합성 응답을 실제 Jev 응답으로 표시하지 않는다. 정상 개작/생성, 인용/금지, 사용자 명시 요청, 위조 권한, 외부 action/target/options/내용 변경, 낮은 확신과 정밀 귀속 미확정의 반례를 확인한다.

현재 역사17요청/예약1088000과 CLI3회는 보존한다. 이번에는 새 유료 run/예산·모델 변경·UI/runner/키 절차를 만들지 않는다. 후보와 독립 검토 후 관리가 다음 최소 실제 검증을 정한다. 모델 효과·실제 공격 보호·전체 MVP는 미완료다.

## 2026-10-17 시연 우선 적용

위 수치는 최초 후보 배정 시점의 역사 기록이다. 이후 실제 V5 평가까지21요청/예약1344000이 기록됐다. 사용자는 정확한 인과 증명보다 시연을 우선하도록 정정했다. 인과/정밀 귀속 미확정은 시연 연결의 보류 사유가 아니며 NOT_ESTABLISHED로 표시한다. 현 V5 행동/귀속 분리와 권한·무결성·.90은 유지하고 기존 gateway/시연 경로에 연결한다. 정상 CONFIRM의 사람 승인 시연은 허용하되 자동 정상 성공이나 전체 MVP 완료로 표시하지 않는다. 다음 배정/제안 한도는16번 계획과 V5_DEMO_INTEGRATION_PROMPT.md가 우선하며 실제 모델 호출은 준비된 한도를 사용자가 선택하기 전까지0이다.
