- 기존 B의 최종88파일/대표 제품30·peer8·브라우저7/추가3과 시연 근거는 당시 범위에 유효하다. 과거 LIVE 정상/NO_ATTACK_ATTEMPT는 현재 F3 판정의 증거가 아니다.
- C/D 전수 운영·공급망·가이드 보강은 제출 전 범위다. 현재 적용 P0와 R-B-002를 제외하지 않는다. 20/49 근거를 관련 코드에 적용하고 원문/시험/발견·조치·재진단을 연결한다.

## 3. 세션의 책임과 정본 소유권

사람 개발자 1명이 하나의 개발 세션을 중심으로 진행한다. 예선 기획서의 4인 분담은 과거 계획이며 현재 개발 인력으로 계산하지 않는다. AI 서브에이전트는 선택적인 구현 보조·검토 역할이다. 별도 AI 검토는 작성자와 역할·문맥을 분리하는 내부 품질 점검이며 추가 사람이나 주최 측 공식 진단을 의미하지 않는다. 같은 AI가 자기 결과만 재독한 경우에는 독립 검토 완료로 기록하지 않는다. 제출 제작의 다른 팀원 지원도 확정 전 일정에 넣지 않는다.

| 세션 | 하는 일 | 쓰기 범위 | 최종 판단 |
|---|---|---|---|
| 관리: 현재 채팅 | 범위·일정·가이드 적용·ADR·작업 배정·결과 대조·상태 승인 | `docs/plans/`, `harness/build_tasks.json`, `AGENTS.md`, 계획 진입 링크 | 증거를 확인해 DONE·다음 단계·출시 가능 범위 판단 |
| 구현: 다른 사용자 세션 | 배정 범위의 코드·관련 시험·통합·실행, 일상 구현 선택 | work pack에 명시된 코드/시험/설정 파일, 자기 RESULT·증거 폴더 | 자기 실측을 보고. 전역 장부의 DONE을 직접 확정하지 않음 |
| 독립 검증: 별도 AI 세션/서브에이전트 | diff·가이드 항목·실제 효과·경쟁/장애·재현 검증. 개발 중 검토는 읽기 위주, 서비스 재현은 개발 세션의 변경을 멈춘 뒤 수행 | 자기 검토 RESULT와 안전한 증거. 기본적으로 제품 소스 읽기 전용 | PASS/FAIL/NOT_RUN와 재현 근거를 관리 세션에 인계 |
| 제출 제작: 별도 세션 | 검증된 결과에서 영상·발표·개요서·포스터 제작 | 배정된 제출 원본과 내보내기 폴더 | 미검증 기능/수치를 성과로 쓰지 않음 |

구현 세션 내부에 orchestrator를 두어 공통 DB 전이·공용 테스트 설정·통합을 한 작성자가 맡을 수 있다. **관리 세션의 정본 소유권과 코드 통합 담당을 혼동하지 않는다.** 현재 HTTP→TLS 전환에 필요한 docs/mvp·OpenAPI 서버/버전·런처의 기계적인 동기화는 ADR-S01과 WP-MVP-01에 지정한 범위에서 사전 위임한다. 그 밖의 상태·권한·정책 의미 변경은 관리 세션의 판단 대상으로 남긴다.

같은 `C:\sogaeding`을 쓰는 세션들은 파일을 즉시 공유한다. 독립 세션이라는 이유로 파일이 격리되지는 않는다. 동시에 쓰는 경우 work pack별 **실제 파일/하위 경로의 단일 작성자**를 지정한다. 공통 계약·의존성·Compose·conftest·작업 장부의 동시 수정을 금지한다. 새 배정 전에 Git 변경과 상대 세션의 결과를 확인하고 사용자 변경을 덮어쓰지 않는다.

## 4. 작업을 넘기고 받는 절차

1. 관리 세션이 work_pack_id, 기준 계약/가이드, 코드 소유자, 읽기/쓰기 경로, 의존성, 완료 조건을 정한다. 02의 프롬프트를 새 개발 세션에 붙여 넣으면 같은 기준으로 착수할 수 있다.
2. 구현 세션은 실제 파일·환경·기존 증거를 확인한다. 함수 분해·오류 메시지 표현·테스트 구현 등 위임 범위의 일상 선택은 스스로 진행한다.
3. 안전 불변조건·상태 전이·도구 범위·추가 외부 서비스·의존성·실험 규모에 영향을 주는 선택은 DECISION_REQUEST로 근거와 선택지를 남긴다. 그 결정과 무관한 작업은 계속한다.
4. 완료/부분 완료 시 [RESULT 양식](../handoffs/RESULT_TEMPLATE.md)을 `docs/handoffs/<work_pack_id>/<run_id>/RESULT.md`에 작성한다. 원기록은 `artifacts/<run_id>/`에 보관하되 키/토큰/민감 원문을 제외한다. 최신 요약과 경로를 이 관리 세션에 전달한다.
5. 독립 검토자가 같은 기준 버전에서 검토·필요한 실제 시험을 수행한다. 실패가 있으면 소유권을 유지한 구현 담당이 수정하고 관련 시험을 다시 수행한다.
6. 관리 세션이 파일·결과·증거를 대조해 장부와 관리 상태를 갱신한다. 작업자의 ‘완료’ 한 문장만으로 DONE으로 올리지 않는다.

RESULT의 경로 전달만으로 별도 채팅이 자동 실행/갱신되는 것은 아니다. 사용자 세션 간 전달은 명시적으로 배정한 인계나 사용자의 전달로 수행한다. 현재 문서는 다른 채팅의 자동 생성·상시 감시·자동 메시지 전송 설정이 아니다.

사용자의 기본 운영 순서는 **개발 세션 1개 → 같은 변경 버전의 별도 AI 검토 → 이 관리 세션에 RESULT/REVIEW 경로 전달**이다. 매 함수·커밋마다 세션을 오가지 않고 얇은 연결·전체 core·제출 후보 같은 게이트에서 인계한다. 문서 3개와 진단 장부는 구현하면서 갱신하며, 긴 문서 작성 완료를 개발 착수의 추가 조건으로 만들지 않는다.

## 5. 완료와 변경을 판정하는 규칙

| 상태 | 의미 |
|---|---|
| TODO / IN_PROGRESS / BLOCKED / DONE | 구현 작업 상태. BLOCKED에는 이유·영향·다음 행동을 기록 |
| PASS / FAIL / NOT_RUN / BLOCKED | 개별 시험 결과. 아직 실행하지 않았으면 NOT_RUN |
| 기능 core 부분 완료 | REPLAY의 실제 집행 일부가 동작하지만 필요한 보안/화면/시험이 남음 |
| core 완료 | AC-01~08·10, 관련 NT/AT, 가이드의 적용 P0 및 보호 전송 보충 게이트 통과 |
| LIVE 완료 | AC-09, 실제 Codex·모델·MCP·정상 결과·공격 시도 여부와 AT-15를 확인 |
| MVP 동작 검증 완료 | ADR-M01의 핵심 기능·현재 적용 P0·A/B·기본 진단/가이드 근거·로컬 재현·Codex 연결 근거 확인. C/D 전수 보강의 완료는 별도 |
| 2라운드 제출 준비 완료 | 전체 준수 검토·제품 및 제출물 검수·재현·6종 동결 완료. 실제 제출 완료와 별개 |

보안약점 49개·설계 20개는 기능 확정에 따라 적용성을 검토한다. 코드가 없다는 이유로 비적용/PASS를 확정하지 않는다. 비적용은 기능·호출 경로·의존성까지 검토한 근거와 독립 검토를 갖춘 상태다. 미점검은 PASS가 아니다. 가이드의 목적과 맞지 않는 오래된 예제를 그대로 복사하지 않는다.

최신 [ADR-M01 MVP 완료 범위](decisions/ADR-M01_mvp_completion_scope.md)가 이전 문서의 ‘C/D 전체가 끝나야 MVP 완료’ 표현을 대체한다. 필수 PDF 개발 기준과 적용 P0는 유지하고, 키수명/운영 전체 조합과 전수 제출 진단은 MVP 이후 제출 전 단계에서 완료한다. 현재 MVP 판정은 B의 결과를 받은 뒤 수행한다.

첨부 IMG-01~09에 따른 요구 분석·위험/외부 인터페이스 설계·코딩 표준·소스 정적 진단·실행 중 동적 보안 검증을 모두 추적한다. 정적 경고 0건이나 IPI 차단 시험은 49개 전체 진단을 대체하지 않는다. 최초 발견→수정→동일 조건 재진단 이력을 보존하고, 구조적 예방의 실제 코드·시험을 개발기획서 제2항에 연결한다.

새 미션/규칙이 도착하면 원문·수신일을 기록하고 요구사항→코드→시험→가이드→6종 산출물의 영향을 대조한다. 일정과 범위를 바꾸되 적용 P0 보안을 삭제해서 시간을 맞추지 않는다. 상세 운영 기준과 공개 공고가 충돌하면 차이를 남기고 확인 대상으로 둔다.

## 6. 이 세션에 결과를 전달할 짧은 입력

```text
작업: WP-MVP-01 / run_id: ...
RESULT: docs/handoffs/WP-MVP-01/<run_id>/RESULT.md
기준 계약/정책: ... / commit 또는 안전한 변경 목록: ...
실제 PASS/FAIL/NOT_RUN: ...
가이드 검토·미준수·보호 전송 결과: ...
관리 결정이 필요한 내용: ...
이 결과를 검토해 작업 장부와 다음 계획을 갱신해줘.
```

관리 세션은 이 입력과 실제 파일을 대조하면 재개할 수 있다. raw 모델 응답·전체 로그·실제 API 키를 붙여 넣을 필요는 없다.
