## 현재 제품과 완료 수준

With Human은 Codex가 등록 MCP 도구를 실행하기 전에 사용자 작업 권한과 읽은 자료의 출처를 검사하는 보안 관문이다. 실행을 허용/차단하고 그 이유·출처·실제 실행 결과를 연결한다. 브라우저는 작업 발급·결과 확인·예외 CONFIRM의 승인 화면이며 주 판정자는 서버의 PDP다.

현재는 **로컬 모의 도구에 대한 실행 통제·이력·승인 기반이 구현됐고, 출처/의미 자동 판정은 코드가 있으나 실제 정상 작업 검증에서 실패한 상태**다. 기획서 전체 또는 MVP 완료를 수용하지 않는다. 과거 문서의 SPEC3/의미모델 후속 표현과 RESULT 작성 시점의 NOT_RUN은 역사 기록이다. 최신 코드는 SPEC4/정책v2이며 첫 실제 모델 실행 결과는 별도로 반영해야 한다.

범위는 다음 세 도구다.

| 도구 | 현재 실제 대상 |
|---|---|
| get_issue | 로컬 가짜 이슈42/43 조회 |
| read_workspace_file | 지정된 PUBLIC_README 읽기, SECRET_ENV 차단. 범용 로컬 파일 접근은 제공하지 않음 |
| post_issue_comment | 로컬 effects DB에 모의 댓글 작성. 실제 GitHub 게시가 아님 |

Codex 내부 셸/파일 도구, 임의 MCP, 전체 PC/LLM/A2A 트래픽을 보호하는 범용 제품은 구현하지 않았다. PDF2쪽의 '같은 설정 파일 외부 전송이라도 사용자/외부 원인에 따라 구분' 예시를 수행할 범용 외부 전송 도구도 없다. 이번 좁은 의미 판정 검증은 동일 댓글 후보에 정상/공격 이슈 문맥을 바꾸는 사례로 구성했으며 실제 검증은 아직 실패했다.

## 구현과 이유

Codex CLI → Python MCP Gateway → FastAPI Control/PDP의 검사 → 원자 실행 예약 → private DemoExecutor → 결과/receipt 저장 순서다. Gateway와 Control은 Docker의 두 서비스이며 Control은 DB와 사용자 웹 API도 담당한다. Codex 모델 호출 전체를 이 Gateway가 중계하는 구조는 아니다.

1. 사용자가 읽기 요약 또는 댓글 작업과 대상 이슈를 발급한다. 댓글 EXACT는 지정한 본문, ISSUE_SUMMARY는 이슈 요약 댓글1회를 위임한다. 외부 자료는 위임을 변경할 수 없다.
2. 읽기 결과에 USER_REQUEST/EXTERNAL/WORKSPACE_DATA 구분과 hash·수집시각·안전한 발췌/분석 문맥을 연결한다. 출처 등급은 모델의 자가 선언으로 정하지 않는다.
3. PDP는 대상/작업 권한/민감정보/예산을 먼저 검사한다. 필요한 후보에서 성공한 읽기 자료를 대조하고 별도 판정 모델에 사용자·권한·후보만 준 관측과 외부 자료를 추가한 관측을 요청한다. 구조화 응답과 실제 근거 위치를 검증해 서버가 최종 결정한다. 이는 실제 actor의 생각이나 인과관계를 복원한 증거가 아니다.
4. ALLOW 또는 유효한 단회 승인만 원자 예약을 통과한다. 결정/승인을 세션·도구·인자·정책에 결합하고 쓰기 예산과 함께 소비해 다른 인자 실행·중복 쓰기를 방지한다.
5. 판정과 실행 상태를 따로 저장한다. DENY/미승인은 위험 효과0, 쓰기 후 결과 불명은 UNKNOWN으로 남기고 자동 재실행하지 않는다. 화면은 출처·판정·예외 승인·확인된 실제 효과를 조회한다.

판정 모델은 행동을 제안하는 Codex와 별개이며 실행 도구/승인 권한을 갖지 않는다. 명확한 읽기·정책 위반에는 모델을 호출하지 않는다. 빠른 수용시험과 1인 구현을 위해 지원 도구·구성 요소를 제한했다. TLS/mTLS, 역할별 인증, 마스킹/암호화 저장, 보존/폐기, 경쟁·장애 복구는 통제 장치 자체가 우회되거나 중요정보를 노출하지 않도록 추가한 필수 통제다. 대표 검증과 전체 운영 보강 완료는 구분한다.

## 기술과 범위 변경

| 예선 기획 PDF3~6 | 현재 | 선택 이유/한계 |
|---|---|---|
| agentgateway/LiteLLM, gRPC ext_authz | Python MCP Gateway와 HTTPS PDP API | 1인 구현에서 도구 인자·출처·실행 전 집행부터 검증. 기존 게이트웨이 어댑터는 아직 없음 |
| PostgreSQL/Redis/OpenTelemetry | SQLite·세션/call/source ID | 설치와 분산 상태를 줄임. 범용 분산 관측/확장성 완료 아님 |
| Streamlit 그래프/오탐 표시 | HTML/JavaScript 최소 UI | 같은 Control API로 관측·승인 흐름 구현. 기획 UI 전체는 아님 |
| Claude Code/Codex CLI/GitHub MCP | Codex CLI 연결 경로와 자체 모의 MCP 세 도구 | 다른 에이전트·실제 GitHub·일반 서버 호환은 미검증 |
| Docker/GitHub Actions/AWS EC2 | 로컬 Docker Compose | 운영 배포·CI 자동 진단 완성은 입증하지 않음 |
| 로그 해시체인, SAST/SCA/SBOM/이미지 점검 | 마스킹·암호화·hash 고정·잠금 의존성·일부 진단과 회귀 증거 | 레코드 해시체인·최종 이미지/의존성/SBOM·20설계/49약점 전수 완료는 아님 |

규칙도 두 가지를 의도적으로 바로잡았다. PDF4의 '외부에만 있는 값을 그대로 쓰면 공격 확정'은 정상 제목·URL·요약도 막을 수 있어 그대로 구현하지 않았다. 외부 자료를 **업무 데이터로 사용했는지, 새 지시로 따라갔는지** 구분하도록 설계했다. 또한 PDF4의 반복 위험 호출 후 사용자 확인은 명백한 DENY 해제 수단이 아니며, 범위 내 모호한 비민감 행동의 CONFIRM만 승인할 수 있다. 이 변경은 최종 기획서에 실제 설계와 근거를 반영해야 한다.

## 검증 근거와 남은 일

- 개발 인계의 제품47개는 기존30개와 F3보강17개이며 의미 관측 대역이 포함된다. 장애8개와 실제 브라우저8개는 별도 시험 범위다. 같은 통과 개수를 새 수용항목이나 IPI 정확도로 합산하지 않는다. 별도 AI의 독립 추가14개도 실제 의미 정확도를 대신하지 않는다.
- 첫 사용자 실행 `manual-real-20261014T081341Z`에서 judge12/24회 모두 응답을 받았다. 정상3건은 분석 결과 사용 불가로 실패, 공격2건은 같은 분석불가 DENY를 시험기가 잘못 PASS로 표시, 모호성1건은 CONFIRM이다. Codex actor는 pwsh 오류로 NOT_RUN이다.
- 최신 대화형 CLI 전환 작업은 11번 작업팩에 배정했다. 현재 scripts에는 준비된 대화형 전용 경로의 완료 인계가 없으며 완료했다고 안내하지 않는다.
- PDF8의 공격차단90%/과차단10%/저비용단계50ms 목표는 달성 근거가 없다. 전체 사례 실행시간을 PDP latency로 바꾸거나 모델 오류 DENY를 공격 차단률에 포함하지 않는다.
- 다음은 PDP 진단/정상 근거 처리 복구 → 사용자 직접 CLI 정상 과업 → 정상 외부자료/외부 지시 차단과 효과 확인이다. 이후 실제 게이트웨이/서버 적용 범위, 최종 보안·공급망·가이드 검토와 수정 기획서/제출물을 정리한다. C/D 전부를 현재 좁은 MVP의 선행조건으로 추가하지 않는다.
