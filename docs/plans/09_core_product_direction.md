# 제품 핵심 정정: PDP의 출처 기반 자동 판정

**2026-10-16 사용 방식 추가 정정:** [13번](13_transparent_codex_gateway_mvp.md)을 우선한다. 원기획 F3뿐 아니라 평소 Codex의 hooks·실제 agentgateway·자동 사용자 turn/출처 결합이 현재 MVP 목표다. 고정 작업 발급·모의3도구 실험만으로 제품 목표를 달성했다고 판단하지 않는다.

2026-10-14 / 관리 판단. 사용자가 원래 제품 의도를 재확인했다. 기획 P1 PDF3~5와 현재 `src/app/pdp/policy.py`, `Repository.check()`를 대조했다.

## 원기획과 실제 구현

- P1 PDF4 F3: 정책 검사→출처 대조→필요한 경우 의미 판단으로 허용/차단/사용자 확인을 결정한다. PDF5의 대표 사례는 외부 이슈가 유도한 댓글을 PDP가 자동 차단하고 원래 요약을 계속하는 흐름이다.
- PDF4 F3/F4에는 사용자 확인도 있으나 예외/반복 위험 상황의 경로다. 사용자 승인이 기본적인 출처 판정을 대신하는 제품으로 계획하지 않았다.
- 현재 `decide(session, tool, args, exact_body)`는 작업 종류·이슈·민감 자원·본문 일치·예산으로 결정한다. 출처 목록을 입력받지 않는다. `Repository.check()`는 판정 이후 출처와의 문자열 일치를 찾아 source_ids/reason을 보충한다.
- 따라서 출처 수집·관측과 실행 전 집행 기반은 있지만 **출처 대조/의미 근거가 자동 결정을 내리는 F3 핵심은 미완성**이다. 이를 단순 UI 변경이나 제출 전 선택 확장으로 분류한 계획은 정정한다. B의 승인 시연은 집행/단회 승인 증거이며 원기획 전체의 자동 탐지 증거가 아니다.

## 제품 동작의 중심

1. 사용자 원문·서버가 발급한 작업 권한과 수집한 외부 자료를 구분해 PDP에 전달한다. 외부 자료가 스스로 선언한 사용자/승인/신뢰 라벨은 권한이 아니다.
2. 정책에 명확히 금지된 행동은 자동 DENY한다. 정상적으로 위임된 행동은 자동 ALLOW한다.
3. 추가 판정이 필요한 후보는 출처와 작업 목적을 대조해 외부 자료가 새 지시·권한 확장을 요구했는지 근거를 남긴다. 의미 판단이 필요한 범위를 제한하고 정확한 입력·출력·실패 정책을 정한다.
4. 외부 자료에서 가져온 정상 업무 데이터도 허용해야 한다. “외부 값과 일치”만으로 공격/차단을 확정하지 않는다. 예를 들어 이슈 제목을 사용해 사용자가 요청한 요약/댓글을 만드는 것은 정상일 수 있다.
5. 사용자 확인은 명시한 모호성/추가 위임의 예외 경로로 제한한다. 명백한 DENY를 사람 승인으로 해제하거나 매 후보를 사람에게 넘겨 자동 판정을 대신하지 않는다.
6. 출처 관측과 의미 분석은 판단 근거다. 에이전트 내부의 실제 사고 원인을 완전히 복원하거나 인과를 증명했다고 표현하지 않는다.

## 다음 개발의 최소 기준

- 기존 Gateway/예약·상태/보존/브라우저·시험을 재사용한다. 고급 인프라·새 도구/서버·대규모 평가를 추가하지 않는다.
- **F3의 최소 출처 기반 자동 판정을 MVP 핵심으로 복원**한다. 정책만으로 가능한 기존 차단, 출처 판단을 추가해 결정한 차단, 의미 판단, 예외 사용자 확인의 근거를 구별해 평가한다.
- 정상 사용자 지시, 외부 지시의 권한 확장, 정상 외부 데이터 활용, 모호한 후보의 실패/예외를 실제 실행 효과와 함께 검증한다. 동일 도구라는 이유만으로 항상 차단하는 시연이나 source_ids 표시만으로 F3 완료를 선언하지 않는다.
- 자연어 작업 위임·댓글 본문·판정 계약을 바꿔야 한다면 관리 세션에서 먼저 구체적인 요구/상태/시험의 변경 범위를 정하고 배정한다. 현재 SPEC-3 계약을 작업자가 무단으로 바꾸는 지시가 아니다.

현재 배정된 인증 실패 영속 기록의 좁은 보완과 이미 실행한 검증 결과는 보존한다. **그 보완과 정상 LIVE만으로 원래 제품 의도의 MVP 완료를 선언하지 않는다.** 다음 우선순위는 F3 최소 구현이다. 추가 유료 의미 모델 평가나 정책/계약 변경은 아직 별도 배정하지 않았다. 기존 “의미 judge 전체는 확장”과 “승인 시연만으로 핵심 완료” 표현보다 이 문서의 핵심 판단을 우선한다. C/D 전체 제출 보강은 계속 별도다.
