# WP-MVP-FINAL-01: MVP 필수 잔여 마무리

> **제품 핵심 정정:** [09 제품 방향](09_core_product_direction.md)을 우선 적용한다. 이 문서의 인증 감사/정상 LIVE 보완은 필요한 안정화지만 원기획 F3 자동 판정의 완료를 대신하지 않는다. 현재 배정된 보완은 보존하며, 이후 F3 최소 구현의 계약/시험 범위를 관리 세션에서 정한다. 이 작업만으로 전체 제품 MVP 완료를 선언하지 않는다.

PLAN-2 / 2026-10-14 KST. [ADR-M01](decisions/ADR-M01_mvp_completion_scope.md)에 따라 현재 노출 기능의 필수 잔여만 보완한다. **R-B-002 인증 실패 영속 추적 → 관련 회귀·별도 AI 검토 → 현재 후보 정상 LIVE 1회/시연 근거 → 관리의 MVP 동작 완료 판단**이 이번 범위다. C/D 전체를 시작하는 배정은 아니다.

- [B RESULT](../handoffs/WP-HARDEN-01/20261013-browser-b-dev/RESULT.md), [B REVIEW](../handoffs/WP-HARDEN-01/20261013-browser-b-review/REVIEW.md), [B 관리 판정](reviews/WP-HARDEN-01_B_20261014_management.md)을 읽는다. 현재 SPEC-3 / policy `mvp-2026-10-13-v1`이다.
- B 최종88파일 fingerprint `9553fd7be6fb9c60a88c853939216530abad0ababa59a393cac4fa7a9b7b5159`가 관리 확인 시 실제 파일과 일치했다. 제품30/peer8·작성자 B01~08·별도 대표7/추가3·새 프로필 시연 근거를 유지한다. 필요한 변경과 관련 회귀만 추가한다.
- G3 PDF110~112는 인증 제한과 실패 추적, DB/파일 등 영속 저장을 명시한다. 현재 `RequestGuard`의 volatile deque만으로는 추적 요건이 남는다. **이 항목의 P0는 팀의 현재 기능 우선순위 판정이며 대회가 지정한 결함 등급이라는 뜻은 아니다.** 현재 인증 기능을 사용하는 MVP에 필요한 보완으로 확정한다.

## 1. 작은 인증 감사 구현

1. 현재 public Control·internal service·MCP agent 인증 경로를 목록화하고 실패가 어디서 발생/기록되는지 연결한다. 기존 SQLite/로컬 파일과 고정 의존성을 사용한다. 새 SIEM·대시보드·분산 플랫폼·외부 전송은 만들지 않는다.
2. 인증 실패의 서버 UTC·생성한 추적 ID·component/route 분류·허용목록 reason·필요한 제한/횟수 상태를 영속 저장한다. 존재하지 않는 계정이나 잘못된 bearer를 실제 사용자 신원으로 확정하지 않는다. 본문·비밀번호·토큰·Authorization·API 키·원문 오류를 기록하지 않는다. credential 자체나 그 digest를 추적키로 사용하지 않는다.
3. 로그/카운터의 저장 권한·원자적 갱신·시간창·수명·최대 저장량/폭주 한도를 명시한다. 기본 보존은 A의24시간 원칙을 재사용하고, 집계하는 경우 시간구간·횟수·마지막 실패와 집계 의미를 보존한다. 무한 per-request append로 디스크를 채우지 않는다.
4. 같은 로컬 배포에서 기록이 재시작 뒤에도 남는지, 제한 시간창의 상태를 재시작으로 무조건 초기화하지 않는지 확인한다. 관련 public/internal 프로세스가 같은 정책 저장소를 사용할 때 동시 접근을 원자적으로 처리한다. 지원하지 않는 다중 host/분산 운용을 구현했다고 주장하지 않는다.
5. 필수 인증 감사 저장 실패는 제한 시간 내 안전한 오류로 처리하고 보호된 작업/도구가 계속 실행되지 않게 한다. 기존 reason/응답 계약·DENY/승인·예산 정책을 유지한다. 공개 로그 조회 API는 추가하지 않아도 된다. 관리자용 안전한 로컬 검사로 증거를 확인할 수 있다.

최소 검증은 정상 인증/댓글, wrong·missing·cross-role·expired 인증 실패의 영속 기록, 프로세스 재시작·관련 동시 접근, 폭주 한도와24시간 정리, 저장 실패 시 추가효과0, 로그/DB/응답의 credential canary 비노출이다. 필요한 원문을 직접 읽고 입력→인증→기록/제한→실제 효과를 대조한다. B08의 기존 제한/정상 회복도 유지한다.

## 2. 회귀·검토·정상 LIVE

- 변경 전과 각 최초 시험/진단 직전 manifest를 명령 UTC·exit·원본에 연결한다. 이전 실패를 최종 수정판 fingerprint로 덮어쓰지 않는다. R-B-002의 최초 공백→수정→재진단을 FINDINGS에 연결한다.
- 기존 A 제품/fault와 B의 영향받는 실제 브라우저 정상·승인·거절·XSS/credential·인증 제한을 회귀한다. 전체 시험을 이유 없이 반복하지 않고 변경 영향과 남은 미실행을 명시한다. 별도 AI는 새 diff·새 인증 감사와 대표 사용자 흐름·effects를 검토한다.
- 현재 후보를 별도 로컬 시험 runtime에 반영해 검증한다. 기존 키/DB/볼륨/원증거는 삭제하지 않는다. 기존 시연 앱을 갱신할 필요가 있으면 동일 runtime의 정상 재기동과 health를 확인하고 사용한 코드 fingerprint를 남긴다.
- **관리의 좁은 LIVE 배정:** 고정 로컬 issue의 정상 요약 **1회**, 기존 관측 모델 `gpt-5.6-luna`와 공식 런처 `scripts/run_codex_live.ps1`을 사용한다. 먼저 DryRun·CA·endpoint·최초 원문/세션 결합·모델 설정을 확인하고 실제 Run은 최대180초·자동 재시도 없이1회로 제한한다. 공격/다른 모델/대규모 평가는 배정하지 않는다. 이1회 외 추가 유료 호출은 판단 요청한다. 키 값은 채팅·프롬프트·증거에 넣지 않는다.
- 사용 가능한 키/모델·검증된 TLS가 없으면 LIVE는 NOT_RUN/BLOCKED 사유를 남기고 나머지를 완료한다. 실패면 FAIL을 그대로 보존한다. 기존 LIVE 증거의 변경 영향을 분석해 재사용 가능성을 검토자가 제안할 수 있으나 새 후보에서 실행했다고 소급하지 않는다.
- 정상 최종 답변·실제 MCP 읽기·원문 digest·timeline/effects와 최종 후보를 연결한다. UI/REPLAY·LIVE는 서로 다른 증거다. 모델이 공격할 때까지 반복할 필요가 없다.

## 3. 소유권과 종료

기존 개발 세션의 단일 통합 작성자가 `src/app/control/`, `gateway/`, 필요한 `storage/`·공통 코드, 관련 `tests/`, 로컬 시험/증거 도구와 현재 시연·런처 설정의 필요한 최소 변경, 자기 `docs/handoffs/WP-MVP-FINAL-01/<run_id>/`와 ignored artifact를 작성한다. 기존 lock/공개계약/권한·상태 의미를 유지한다. 내부 인증 감사 테이블·비파괴 migration·기동 정리와 시험은 사전 위임한다. 신규 외부 서비스/정책 재설계가 필요하면 해당 부분만 결정 요청한다.

plans·harness 장부·AGENTS·설치 skill·기존 handoff/원증거는 수정하지 않는다. 결과는 새 RESULT/SECURITY_DESIGN/GUIDE_APPLICABILITY/FINDINGS 및 별도 REVIEW로 인계한다. **MVP 필수 잔여**와 **제출 전 C/D 보강**을 나누고 임의로 새 완료 조건을 늘리지 않는다. R-B-002 처리 결과, 정상 LIVE/시연, 로컬 URL·사용자 재현 절차를 관리 세션이 검토해 MVP 동작 완료를 판정한다. 현재 문서 작성으로 완료를 선언하지 않는다.
