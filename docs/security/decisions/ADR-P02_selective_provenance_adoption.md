# ADR-P02: 인자별 출처·문맥 분석의 선택적 채택

상태: **ACCEPTED（설계·개발 배정, 구현/모델 성능 완료 아님）**

날짜: 2026-10-16, Asia/Seoul. 사용자 지시: 가치가 있으면 관리 판단으로 채택하고 그렇지 않으면 원래 계획 유지. 비교 검토를 근거로 다음을 결정한다.

## 결정

기존15번의 규칙 검사→서버 출처 대조→미확정 의미만 Jev→서버 최종합성·gateway 집행을 유지한다. 새안 중 **행동/대상/옵션/전송 내용별 출처 분석, 값이 사용된 문맥의 역할 분류, 복수 출처와 출처 미확정의 명시적 처리**를 WP-PDP-JEV-01에 포함한다.

본문·URL·경로·코드·설정값에 inline 마커를 삽입하고 실행 직전 제거하는 기능은 **이번 MVP 범위에서 제외**한다. 후속 필수 실험/완료 게이트로도 추가하지 않는다. 서버 출처 원장을 유지하며 에이전트가 보는 원문과 실제 도구 인자를 라벨 기능 때문에 수정하지 않는다.

## 필요한 구현 의미

1. 실제 도구 스키마·검증된 parser로 action/target/options/payload를 추출한다. 도구별 비적용 슬롯은 구별한다. 모델이 새 실행 대상/인자를 발급하지 못한다. 해석하지 못한 복합 명령의 슬롯을 추정으로 확정하지 않는다.
2. 슬롯의 관측된 값과 연결되는 source/span을 서버 catalog에서 찾고 복수 링크를 허용한다. 원문 정확 일치/정규화 대조, 모델이 제안한 연관, 미확정은 구별한다. 그 링크는 관측 근거이며 실제 인과·사용자 승인 증명이 아니다.
3. 외부 문단에 등장한 .npmrc의 출처와 실제 로컬 대상 파일의 identity를 분리한다. USER/LOCAL/EXTERNAL의 origin과 권한/신뢰 정책을 혼동하지 않는다. LOCAL은 자동 신뢰가 아니다. 모델·문서의 자칭 사용자/source ID를 승격하지 않는다.
4. 정책만으로 미확정인 민감 슬롯의 관련 span에 한해 권유/실행 지시, 사실·데이터, 금지·인용, 미확정의 문맥을 Jev가 관측하게 한다. 문서의 모든 값에 사전 분류를 강제하지 않는다. 동일 snapshot/문맥의 질문은 배칭·안전한 캐시를 검토할 수 있으나 A/B 상태 격리는 유지한다.
5. 비적용, 관측된 출처 없음, 출처 미확정, 필수 분석 실패를 구분한다. 출처 미확정을 실행 상태 UNKNOWN과 같은 enum/전이로 처리하지 않는다. source가 없는 정상 생성값을 일괄 금지하거나, source가 없다는 이유로 안전하다고 허용하지 않는다.
6. 외부+권유+위험은 분석 신호이며 유일한 허가/거부 공식이 아니다. 코드 정책 위반은 출처와 무관하게 DENY한다. 정책 내 의미 불확실성만 제한된 CONFIRM 예외, 인증/API/필수 근거 장애는 차단한다. 정상 외부자료 활용·정상 개발이 계속 가능해야 한다.

기존 민감정보/권한·정확 인자/hash·원자 예약/단회 승인·DENY 해제 금지·UNKNOWN 재시도/환불 금지·같은턴 장애 후 유료 반복 중단·로그 마스킹/보존은 유지한다. Jev가 정책상 DENY나 권한을 변경하지 못한다.

## 수용 증거

관련 오프라인 회귀에 정상 외부 문서 권고, 위험 문자열의 설명/금지/인용, 데이터 모양의 공격, 파생 설정값, 다중 출처/출처 누락, 로컬 identity 혼동, 위조·stale·cross-session 링크를 포함한다. 안전한 읽기/명백한 금지는 모델0회로 검증한다. 모델 장애/불충분 문맥 때 금지 효과0을 확인한다.

슬롯 분해·출처 링크·문맥 관측·위험 정책을 따로 기록해 어느 근거로 결정했는지 확인한다. 합성/fake 제어 흐름 PASS와 실제 Jev의 한국어 분류/공격 판정 정확도는 분리한다. 새 모델 유료 호출/키·계정 접근/호스트 승인 정책 변경 권한은 이 결정으로 추가하지 않는다.

## 채택 이유와 범위 제한

포괄적인 사용자 의도 추정 대신 검사 대상을 작게 나눠 설명·시험하기 쉽다. 이미 있는 서버 source/catalog와 실행 전 집행을 재사용한다. inline 마커의 유실/위조/데이터 훼손·클라이언트 출력 교체 지원 차이를 제품 필수 경로에 추가하지 않는다. 실제 IPI 탐지율 개선은 아직 미측정이며 정식 taint 전파/인과 증명을 주장하지 않는다.

구현은 별도 개발 세션이 갱신된 START_PROMPT를 따른다. 관리가 전역 상태/DONE을 결정한다. 현재 실행 제품은 여전히 SPEC5/GPT이고 일반 native/hook 사망 fail-open·호스트 auto-review403·공급망 미완료는 별도로 남는다.
