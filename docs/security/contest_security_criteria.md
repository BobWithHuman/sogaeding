## 3. 사람 1명이 관리할 최소 보안 산출물

| 테스트 | `GUIDE_APPLICABILITY.md` 동적 결과 + `FINDINGS.jsonl` | 실행코드 스캐닝·모의침투, 정상/공격·장애/경쟁, UI/DB/effects, 수정 후 같은 조건 재진단 | 실제 배포 대상 경로의 결과·미실행·잔존 위험 분리; 필수 미완료 시 보안 완료 아님 |

외부 인터페이스는 최소한 **사람/브라우저·런처→Control, Codex CLI→MCP Gateway, Gateway→Control, Gateway→등록 fixture/private executor, 서비스→DB/로그, Codex→OpenAI API**를 목록화한다. 각 행에 방향·프로토콜/포트·자격증명/역할·신뢰 경계·입력/출력·중요정보·허용 대상·TLS/상대 인증·timeout/예산·장애 처리·코드/시험을 기록한다. 로컬 파일/DB 경계도 포함하며 모두 외부 인터넷 연결이라는 뜻은 아니다. 공개되지 않은 executor가 인증·예약 우회로 호출될 수 있는지 별도로 확인한다.

표준코딩 정의에는 최소한 다음 공통 규칙과 실제 적용 위치를 넣는다.

- 입력은 strict schema·범위·길이·깊이·허용목록으로 검증하고 SQL은 파라미터 바인딩한다. 임의 셸/eval/unsafe 역직렬화와 요청값 기반 파일/URL 접근을 노출하지 않는다.
- 인증·객체별 인가는 공통 경로에서 수행한다. 세 역할의 권한을 나누고 사용자 승인과 agent/service 자격증명을 혼동하지 않는다.
- 인증정보 전송은 ADR-S01의 검증된 보호 채널을 사용한다. 안전한 난수·검증된 암호 API를 쓰고 키·원문 중요정보를 코드·로그·오류·UI에 노출하지 않는다.
- ALLOW/DENY/CONFIRM과 실행 상태를 분리하고 검사와 실행 사이 원자 예약·정확한 단회 승인·예산을 강제한다. UNKNOWN의 위험 쓰기를 자동 재시도하지 않는다.
- 외부 문자열은 안전한 텍스트로 출력하고 오류는 최소 정보만 반환한다. 자원 수명·timeout·취소·재시도 한도를 명시한다. mutable 객체 공유로 정책이 변하지 않게 한다.
- 패키지·이미지·도구 출처와 버전/해시를 기록하고 첫 제품 build부터 SBOM/SCA/license를 연결한다. 테스트 전용 우회·debug·실제 비밀을 제출 소스/이미지에 남기지 않는다.

| 수동 검토 | 49약점과 설계20을 코드의 source→검증/인가→sink/상태·효과까지 추적 | 적용/비적용 근거, 파일/함수, 의존성/네이티브 경계, AI 검토 역할·사용자 관리 판정 | 도구 미탐이 곧 수동 검토 완료가 아님. 코드 없는 행은 미구현/미점검 |
| 실행코드 스캐닝 | 가짜 데이터의 로컬 Docker 제품에 실제 인증·입력·헤더·TLS·오류 응답 탐색. 사용 도구/테스트 드라이버·인증·대상 범위를 고정 | 서비스/이미지 버전·대상 URL 범위, 요청 조건·응답·상태/효과, 스캔 미도달 endpoint | 스캐너 도입 자체보다 실제 경로 도달 증거가 필요. 인증 못 한 스캔으로 인증 후 경로까지 PASS 금지 |
| 모의침투·회귀 | 타 세션 접근, 직접 executor/서비스 우회, 승인 재사용/인자 변경/경쟁, 주입·비밀 접근, 장애/report 유실을 정상 요청과 대비 | 기존 NT/AT 및 보완 case ID, 실제 호출/효과 전후, 차단·통과·미시도·오류·미실행 구분 | IPI LIVE에서 모델이 공격을 시도하지 않으면 집행 차단 성공 아님. mock-only는 실행코드 진단 아님 |

동적 진단의 최소 범위는 실제 구현한 경로에 적용한다. **인증 누락·교차 역할/세션, grant/출처 위조, 임의 인자·SQL/경로/명령/URL 입력, XSS/CSRF 및 오류·비밀 노출, wrong CA/hostname/expiry와 필요한 client 인증, 승인 0회/단회/경쟁, 예산·timeout/자원 한도, PDP/DB/전송 장애·UNKNOWN, debug/직접 executor 경로**를 기존 수용시험과 연결한다. 추가 시험은 새 대회 의무 번호를 만들지 않고 팀 내부 사례로 기록한다. 특정 유료 스캐너 도입 의무는 확인되지 않았다.

모든 탐색·공격 입력은 배정된 로컬 테스트 제품·가짜 자료에 한정한다. 외부 OpenAI나 GitHub 서비스를 진단 대상으로 공격하거나 실제 개인정보를 실험 재료로 넣지 않는다. 기존 사용자 요청의 권한 범위 내에서 구현과 검증을 진행한다.

## 6. 최초 진단부터 조치율 근거까지

1. **범위 고정:** 첫 실행 가능한 제품 source/image/lock의 버전·해시, 포함/제외 파일, 도구·룰셋·시간·명령을 `baseline_id`로 묶는다. 초기 개발 하네스의 진단 0건을 제품 baseline으로 가져오지 않는다.
2. **발견 보존:** 도구·수동·동적에서 발견된 항목은 `finding_id`를 발급하고 최초 원본 증거를 유지한다. 같은 원인/위치의 중복은 별도 기록과 `duplicate_of` 연결을 남겨 숨기지 않는다.
3. **판단 분리:** 미분류·정탐·오탐·중복·비적용 후보/확정의 사유, W/SR ID, 영향·우선순위, 검토 역할을 기록한다. 정적 분석 원시 경고 개수와 확정 약점 개수를 혼합하지 않는다.
4. **수정 연결:** 변경 코드/버전, 원인과 구조적 통제, 정상·공격 회귀 case를 기록한다. 수정했다고 표시하는 것만으로 제거 완료가 아니다.
5. **재진단 연결:** 같은 범위·룰셋·재현 조건으로 재검사하고 실제 제거 여부·남은 한계·증거를 기록한다. 범위/도구가 달라졌으면 차이와 비교 한계를 남긴다. 재발은 새 이벤트로 재개방한다.
6. **검토·보고:** 별도 AI 검토가 원증거·diff·실제 효과를 확인하고 관리 세션이 공개할 수치·완료 범위를 승인한다. 최초 기록이나 불리한 결과를 최신 결과로 덮어쓰지 않는다.

`FINDINGS.jsonl`은 팀 개발 증거용 추가형 장부다. **쓰기 권한자가 수정할 수 없다는 암호학적 불변성을 주장하지 않는다.** 버전별 원본 snapshot·해시로 이력을 대조하고 잘못 기록한 정보는 기존 행 삭제 대신 정정 이벤트를 추가한다. 실제 비밀이 실수로 포함되면 공유를 중단하고 사용자 권한 범위의 비밀 제거·회전 조치 및 안전한 정정 사유를 기록한다.

| 필드 묶음 | 최소 필드 |
|---|---|
| 이벤트·버전 | `event_id`, `finding_id`, `event_type`, `recorded_at`, `baseline_id`, `source_version`, `scope_manifest`, `previous_event_id` |
| 발견·분류 | `guide_ids`, `requirement_ids`, `file_function_lines`, `source_sink`, `tool_rule_or_manual`, `evidence_paths`, `classification`, `reason`, `duplicate_of` |
| 조치·재검증 | `change_version`, `control_id`, `test_ids`, `recheck_run_id`, `result`, `remaining_risk`, `reviewed_by` |

아직 발견되지 않은 약점을 실적으로 만들기 위해 코드를 취약하게 작성하지 않는다. `GUIDE_APPLICABILITY.md`에는 **미분류 원시 경고 수, 확인 정탐 수, 그중 재진단 제거 수, 잔존·재개방 수, 오탐/중복/비적용 근거 수, 미진단 범위**를 구분해 보고한다. 아무 제품 진단도 하지 않은 현재는 수치를 0으로 채우지 않고 **NOT_RUN**으로 둔다.

“빌드라인” 정의·분모·공식 산식·오탐 처리·분석 범위는 제공 자료에 없다. 파일/라인 수·source manifest는 재현용으로 기록할 수 있으나 그것을 공식 “빌드라인”으로 확정하지 않는다. 동일 baseline의 확인 정탐 중 재진단 제거 비율은 **팀 내부 추적치**로만 사용한다. 분모가 0이거나 미확정이면 비율을 100%로 쓰지 않는다. 신규 정탐·추가 범위는 별도로 보고하고 줄 수 늘리기·소스 숨기기·진단 제외로 공식 평가를 유리하게 계산하지 않는다.

## 7. 기획서 제2항에 옮길 구조적 설계 근거

C1 PDF26과 IMG-09는 개발기획서 **“2. 주요 기능 및 개발환경”**에 보안약점 예방을 위한 구조적 설계나 구현 방법을 기술하도록 안내한다. 아래는 실제 코드가 생긴 뒤 채울 설명 틀이며 현재 구현 완료 주장이 아니다. 각 행은 `약점/위협 → 공통 통제·신뢰 경계 → 실제 코드/버전 → 실패·공격 조건 시험 → 실제 효과/한계`로 서술한다.

| 구조 설명 후보 | 연결 약점·설계 항목 | 실제로 채울 증거 | 현재 |
|---|---|---|---|
| gateway의 등록 도구와 private executor 단일 집행 경로 | W-15·18·19, SR1-9·SR2-1·4 | 직접 호출·역할 위조 차단 코드, PDP 장애 시 실행0 시험, 보호하지 않는 builtin 경로 | NOT_STARTED |
| 정확한 사용자 권한·세션·action/정책 결합과 원자 예약 | W-19·34·44, SR2-4·SR4-1 | 승인 인자 변경/replay/경쟁·타 call ID 예산 시험, DB 전이와 effects0/1 | NOT_STARTED |
| 고정 자원 ID·strict schema·파라미터 SQL | W-01~03·05·12·43, SR1-1·4·9 | 입력→등록 자원/질의 경로, 악성/경계 입력 거부·정상 결과 | NOT_STARTED |
| 역할 분리·TLS·중요정보 최소수집과 보호 | W-18~25·28·29·31·33, SR2-1~8 | 실제 인증 경로·인증서 검증·credential canary·반복 실패 제한·저장 정책 | NOT_STARTED |
| 안전한 오류·유한 실행·UNKNOWN 및 자원 정리 | W-35~40·45, SR3-1 | 장애/timeout/취소·report 유실·raw 오류/비밀 미노출, 자동 쓰기 재시도 부재 | NOT_STARTED |
| 안전한 UI·세션 격리·불변 정책 객체 | W-04·11·44·46·47, SR1-5·6·SR4-1 | DOM sink/escape·origin·객체 변경·다른 세션 조회 차단 시험 | NOT_STARTED |

SBOM·SCA·lock/이미지 무결성은 제품 공급망 증거로 별도 연결한다. 행동 출처 장부를 SBOM으로 부르지 않는다. 구조 이름이나 다이어그램만으로 예방 효과를 주장하지 않으며 원 기획의 mTLS 등 약속도 실제 구현·시험 범위와 변경 사유를 적는다. 제2항 초안은 `SECURITY_DESIGN.md`를 재사용하고, 검증된 내용만 제출물 계획의 기획서 업데이트본으로 옮긴다.

## 8. 인계 게이트와 상태

작업 장부 T-10에 연결한 내부 게이트는 `PL-SEC-SDLC`(보안 요구·설계·코딩 표준·정적/수동/동적 검증 연결)와 `PL-SEC-DIAGNOSIS`(49개별 도구 범위·보완 검토·발견/조치/재진단 이력)다. 둘 다 **NOT_RUN**이며 기존 NT-01~03/AT-01~15의 18개 제품 시험에 추가되는 증거 기준이다. 주최 측의 새 시험 번호나 공식 채점 산식이 아니다.

개발 세션은 세 산출물의 경로와 코드/시험/진단 버전을 `RESULT.md`에 넘긴다. 관리 세션은 **개발 준비, 기능 구현, 제품 시험, 20/49 적용성·진단, 조치·재진단, 제출문서 반영**을 따로 판정한다. 당일 시간이 부족하면 완료한 안전한 경로와 미완료를 보고하고, 필수 보안을 제거해 MVP 완료를 선언하지 않는다. 추가 인력의 동시 작업 없이 구현→자기 검증→별도 AI 검토→관리 판정 순서를 반복한다.

이번 갱신으로 완료한 것은 첨부 기준 대조와 계획 보완이다. 제품 소스 진단, 실행코드 스캐닝·모의침투, 제품 20/49 전수 판정, 정탐 조치·재진단, 공식 점수 계산은 수행하지 않았다. 원본 가이드와 [03의 P0 게이트](guide_compliance.md), 오늘 개발 계획, [ADR-S01](decisions/ADR-S01.md)의 보호 요구를 계속 적용한다.
